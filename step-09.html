wafpass-server

The central ingestion, persistence, and API layer. It receives wafpass-result.json files from CI, stores historical scans, and exposes REST endpoints for dashboards, webhooks, and integrations.

🧰 Technology stack & patterns

FastAPI

Async Python web framework with automatic OpenAPI docs at /docs and /redoc.

SQLAlchemy 2.x

ORM with type annotations, async drivers, and explicit transaction boundaries.

PostgreSQL

Primary datastore for run history, accounts, and projects. JSONB columns store flexible result payloads.

Pydantic v2

Request/response models and settings management via pydantic-settings.

uvicorn

ASGI server. Use uvicorn main:app --reload locally, gunicorn+uvicorn workers in production.

Docker

Containerised deployment with multi-stage builds and a non-root user.

FastAPI + PostgreSQL persistence layer and REST API.

🖥️ Run the server locally

# Using Docker Compose (recommended)
cd wafpass-server
docker compose -f docker-compose.dev.yml up --build

# Or natively with Python
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

# Start PostgreSQL (or use the docker compose service)
alembic upgrade head
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

# Verify
open http://localhost:8000/docs

🎨 Code style & guidelines

  • Formatter: ruff format with line length 100.
  • Linter: ruff check; keep import blocks clean and sorted.
  • Typing: annotate all route handlers, services, and models; run mypy in CI.
  • Async discipline: use async/await for I/O; CPU work goes to asyncio.to_thread.
  • Transactions: never leak DB sessions; rely on dependency-injected session and rollback on exception.
  • Routes: keep routers thin; business logic lives in services/.
  • Settings: all environment-specific values flow through app/config.py and Pydantic validation.
  • Errors: raise HTTPException with structured detail; log full stack traces server-side.
# Local quality gates
ruff check app tests
ruff format --check app tests
mypy app
pytest

🔐 Authentication & authorisation

The server supports API key authentication for CI ingestion and OAuth2 / bearer token flows for the dashboard. API keys are hashed before storage; never log the plaintext key. Route dependency get_current_user_or_key accepts either path depending on the endpoint's contract.

# POST a result from CI
curl -X POST http://localhost:8000/api/v1/runs \
  -H "Authorization: Bearer $WAFPASS_API_KEY" \
  -H "Content-Type: application/json" \
  -d @wafpass-result.json

# Response
{
  "run_id": "0192e6c4-...",
  "project_id": "my-project",
  "status": "stored",
  "findings_count": 12
}

🧪 Testing strategy

  1. Unit tests: service functions with mocked repositories and notifiers.
  2. Integration tests: FastAPI TestClient against a real PostgreSQL service spun up via Docker or testcontainers.
  3. Migration tests: run alembic upgrade head and downgrade -1 in CI.
  4. Contract tests: POST known wafpass-result.json fixtures and assert the stored JSONB payload matches.
# tests/conftest.py skeleton
import pytest
from fastapi.testclient import TestClient
from app.main import app
from app.database import get_session

@pytest.fixture
def client(db_session):
    def override_get_session():
        yield db_session
    app.dependency_overrides[get_session] = override_get_session
    yield TestClient(app)
    app.dependency_overrides.clear()

📡 REST API surface

The server exposes an auto-generated OpenAPI 3.1.0 contract. You can browse the interactive docs locally at http://localhost:8000/api/v1/docs or download the machine-readable spec at /openapi.json. The docs are generated from the FastAPI routers, Pydantic schemas, and type annotations, so they stay in sync with the code.

🍽️ Ingestion & history

POST /api/v1/runs ingests wafpass-result.json. GET /api/v1/runs/{run_id}, export endpoints (CSV, Jira, Slack) and attestation support full auditability.

🔐 Auth & identity

Bearer-token login/refresh, user management, API-key lifecycle, and OIDC/SAML SSO plus group-to-project mappings.

📋 Controls & compliance

Control packs, active-pack activation, waivers, risk acceptances, and signed validation records with certificate export.

🛡️ Evidence & trust

Evidence uploads, tamper-evident snapshots, public/shareable evidence views, QR codes, and HTML reports.

🤖 Automation

Programmatic scan triggers, sandboxed execution, AI-powered auto-fix with rollback, and notification dispatch.

🏆 Reporting widgets

Public JSON widgets, SVG badges, leaderboards, achievements, and audit-event logging for dashboards and CI badges.

🔢 API versioning strategy

How versions are exposed

  • The current contract is published as version 1.0.0 inside info.version of the OpenAPI spec.
  • Every route is namespaced under /api/v1/.... This keeps major versions isolated at the URL level.
  • GET /version and GET /health are unversioned; clients use them for discovery and probes.
  • Internal-only routes (triggered scans, validation signing, update checks) live under the same v1 prefix but behind stricter auth.

Compatibility rules

  • Within v1 we only add optional fields and new endpoints; we never remove fields, rename paths, or change required request shapes.
  • A future incompatible change will be introduced as /api/v2/... while v1 remains available during a documented deprecation window.
  • Dashboard and integrations pin the major version in their client configuration; the server never auto-upgrades a caller silently.
  • Validation schemas and signed certificates include the API version that produced them, so evidence remains verifiable years later.
# Discover the current API contract
curl http://localhost:8000/openapi.json | jq '.info.version, .paths | keys[0:3]'

# Browse interactive docs (local network)
open http://localhost:8000/api/v1/docs

# Example: ingest a result with a pinned v1 key
curl -X POST http://localhost:8000/api/v1/runs \
  -H "Authorization: Bearer $WAFPASS_API_KEY" \
  -H "Content-Type: application/json" \

⚙️ Configuration

All settings live in app/config.py and are validated at startup. Common variables:

  • DATABASE_URL — PostgreSQL DSN (asyncpg driver recommended).
  • SECRET_KEY — used to sign tokens and API key hashes.
  • CORS_ORIGINS — comma-separated allowed dashboard origins.
  • WAF_RESULT_MAX_SIZE_MB — upload limit for result JSON.
  • WEBHOOK_TIMEOUT_SECONDS — default timeout for outgoing webhooks.

🔒 Security & trust assumptions

  • Run the server behind a TLS-terminating reverse proxy in production.
  • Rotate API keys regularly; revoke leaked keys via DELETE /api/v1/api-keys/{id}.
  • Never return raw API key values after creation; show them once.
  • Validate uploaded JSON strictly against the Pydantic result schema before storing.
