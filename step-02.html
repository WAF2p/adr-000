framework & framework-en

The heart of WAF++. It defines the 8 pillars, the machine-readable control catalogues, and all human-readable guidance. framework and framework-en are the same git repository checked out on two different branches.

📚 What is the framework repository?

The framework repository is the canonical source for the Well-Architected Framework++ itself. It contains:

  • The conceptual introduction, roadmap, and glossary.
  • One Antora module per pillar (Security, Cost, Performance Efficiency, Reliability, Operational Excellence, Sustainability, Sovereign, Agentic).
  • The machine-readable control definitions in YAML, consumed by wafpass-core.
  • Reviewer worksheets, decision guides, and architecture patterns.

The content is written in AsciiDoc and published as an Antora documentation component. The website repo (waf2p.github.io) consumes this component together with its own marketing site.

🌐 German vs English

WAF++ ships in two languages. Both are maintained in the same repository, on separate long-lived branches:

  • German: framework/ → branch main-de.
  • English: framework-en/ → branch main-en.

The two directories are independent working copies of the same git history. You can merge translations, cherry-pick fixes, or release one language before the other.

⬇️ Clone commands

mkdir waf++
cd waf++

# German edition (branch main-de)
git clone --single-branch --branch main-de \
  https://github.com/WAF2p/framework.git framework

# English edition (branch main-en) — same repo, different branch
git clone --single-branch --branch main-en \
  https://github.com/WAF2p/framework.git framework-en

✍️ AsciiDoc writing style & guidelines

  • One idea per paragraph: keep guidance concise and actionable.
  • Use cross-references: link to other pages with xref:pillar-security:index.adoc[] instead of hard-coding URLs.
  • Include IDs: every section should have an anchor, e.g. [#decision-matrix].
  • Controls as code: control IDs, titles, and severities live in YAML under modules/controls/controls/; prose explanation lives in AsciiDoc.
  • Language parity: when adding content to one language, open a corresponding issue/PR for the other branch.
  • No Jekyll/Liquid: this repo is pure Antora/AsciiDoc; website styling comes from waf2p.github.io.
  • Commits: conventional commits, e.g. docs(pillar-security): add encryption decision guide.

🧪 Validate controls locally

The engine reads the same YAML control files, so you can verify syntax and IDs without running a full site build.

# From the pass/ repo, after installing wafpass-core
cd ../pass
wafpass controls list ../framework/modules/controls/controls/

# Or run a quick scan against dummy fixtures
wafpass check ./dummy_code --controls-dir ../framework/modules/controls/controls/ --summary

🛠️ Build & preview workflow

You do not build the framework repo on its own. The website repo runs Antora with this component as a source.

# 1. Clone the website repo alongside framework/
git clone https://github.com/WAF2p/waf2p.github.io.git

# 2. Install dependencies and start the local site
cd waf2p.github.io
npm install          # installs Antora CLI
task deps:install    # installs Ruby/Jekyll deps if needed
task site:serve      # builds Antora docs + Jekyll site

The local playbook (antora-playbook-local.yml) points at the sibling framework/ and framework-en/ directories.

🚀 Framework developer onboarding

  1. Clone framework (main-de) and framework-en (main-en).
  2. Read AGENTS.md and one full pillar module end-to-end.
  3. Start the local site from waf2p.github.io and preview your edits.
  4. Make a small docs fix: correct a typo, add an anchor, or improve a cross-reference.
  5. If the change affects controls, validate the YAML against the engine.
  6. Open a PR against the correct branch (main-de or main-en).

🔗 Relationship to the website

waf2p.github.io is the public surface. It builds a Jekyll marketing site and then runs Antora to generate /docs/wafpp/ from the framework and framework-en components. The website repo owns layouts, navigation, styling, and blog posts; the framework repos own the knowledge.

🗃️ Versioning and releases

  • The component version is declared in antora.yml (e.g. 1.0.2-de, 1.0.2-en).
  • Docs versions are kept in lockstep with control versions where possible.
  • Published URLs follow the pattern https://waf2p.dev/docs/wafpp/{version}-{lang}/.
  • Back-port critical fixes to the current published version branch; develop new content on main-de / main-en.
