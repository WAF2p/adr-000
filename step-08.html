wafpass-dashboard

The browser-based cockpit. It visualises scan history, drill-down findings, trends, and compliance posture for teams and auditors.

🧰 Technology stack & patterns

React 18+

Functional components and hooks. Keep components small and compose through props, not inheritance.

TypeScript

Strict mode enabled. Define shared types in src/types/ and derive API shapes from the backend OpenAPI spec.

Vite

Fast dev server and production builds. Environment variables use VITE_* prefix.

Tailwind CSS

Utility-first styling. Custom design tokens live in tailwind.config.js.

TanStack Query

Server-state cache, loading/error UI, background refetching, and optimistic updates.

Recharts / Chart.js

Trend charts, radar diagrams, and pie charts for pillar distribution and severity.

🎨 Code style & guidelines

  • Formatter: prettier with project config; run npm run format.
  • Linter: eslint with TypeScript and React hooks rules; zero warnings in CI.
  • Components: one component per file; co-locate styles if they are component-specific.
  • Hooks: extract data-fetching and side effects into custom hooks; keep UI hooks lean.
  • Types: no any without justification; prefer interfaces for props and types for unions/derived shapes.
  • Accessibility: semantic HTML, ARIA labels, keyboard focus states, and colour-contrast checks.
  • Performance: memoise expensive renders and chart data; lazy-load route components.
  • Commits: conventional commits, e.g. feat(dashboard): add severity filter.
# Local quality gates
npm run lint
npm run format:check
npm run typecheck
npm run test

🎨 Design system & glass-morphism

The dashboard shares the same visual language as waf2p.dev: soft gradients, translucent cards, subtle borders, and theme-aware colour tokens.

  • Use CSS variables for light/dark palettes; do not hard-code colours.
  • Cards use a semi-transparent background with backdrop blur for the glass effect.
  • Accent colour is the WAF++ blue (#0094FF); severity colours are red/amber/green/neutral.
  • The theme toggle sets data-theme on the document root and persists the choice.
  • Mobile-first grids: 1 column on phone, 2 on tablet, 3+ on desktop.
/* Example glass card (Tailwind + custom CSS) */
.glass-card {
  @apply rounded-2xl border p-6;
  background: rgba(255, 255, 255, 0.72);
  backdrop-filter: blur(12px);
  border-color: rgba(15, 23, 42, 0.09);
}

[data-theme="dark"] .glass-card {
  background: rgba(15, 23, 42, 0.60);
  border-color: rgba(148, 163, 184, 0.14);
}

🧪 Testing strategy

  1. Unit tests: Vitest + React Testing Library for components, hooks, and utilities.
  2. Mocked API: MSW (Mock Service Worker) intercepts calls during tests and Storybook.
  3. Visual regression: Storybook stories for every reusable component.
  4. E2E: Playwright runs login, upload, navigation, and export flows against a real backend.
  5. Accessibility: axe-core in CI catches missing labels and contrast issues.
# Watch mode during development
npm run test -- --watch

# Run a single test file
npx vitest run src/components/charts/PillarChart.test.tsx

# E2E
npx playwright test

🔌 API integration

The dashboard consumes wafpass-server REST endpoints. All server-state lives in TanStack Query; local UI state lives in Zustand or React Context. Generated types from the OpenAPI spec are kept in src/api/openapi.ts and refreshed when the backend contract changes.

// src/hooks/useRuns.ts example
import { useQuery } from '@tanstack/react-query';
import { apiClient } from '@/api/client';

export function useRuns(projectId: string) {
  return useQuery({
    queryKey: ['runs', projectId],
    queryFn: () => apiClient.get(`/projects/${projectId}/runs`).then(r => r.data),
  });
}

🗃️ State management rules

  • Server state: TanStack Query only. Do not mirror server data in a global store.
  • Local state: useState for component-local UI (filters, toggles).
  • Shared UI state: Zustand for theme, sidebar, notifications, and active project.
  • Derived data: compute charts and aggregates in memoised selectors, not in render body.

🔒 Security & trust assumptions

  • Never store API keys in frontend code or environment files that ship to the browser.
  • The dashboard relies on the server's auth layer; route guards redirect unauthenticated users.
  • Sanitise any user-generated content rendered as HTML to avoid XSS.
  • Keep charting libraries updated; they handle SVG/DOM and can introduce DOM-based XSS if compromised.
