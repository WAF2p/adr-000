wafpass-core

The IaC compliance engine. It scans Terraform, Bicep, CDK, and Pulumi code, evaluates controls, and emits the canonical wafpass-result.json for the server and dashboard.

🧰 Technology stack & patterns

Python 3.11+

Modern Python with type hints, pathlib, and asyncio for parallel rule evaluation.

CLI

Composable command-line interface built on Typer/Click, with nested groups and generated help text.

Pydantic v2

Models for controls, findings, and the result schema; strict validation and serialisation.

Pluggy

Hook-based plugin system so controls and IaC parsers live in separate packages.

Jinja2

Human-readable finding messages and report templates that can be localised.

Rich / structlog

Coloured terminal output and structured JSON logs for CI environments.

Engine, CLI, result schema, and bundled controls.

🖥️ Run the engine locally

# Install in editable mode
mkdir waf++ && cd waf++
git clone https://github.com/WAF2p/wafpass-core.git
cd wafpass-core
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

# Verify the CLI
wafpass --help
wafpass version

# Scan a sample
wafpass check ./tests/fixtures/terraform --output json \
  --project demo --stage local

# Push to a local server
wafpass check ./tests/fixtures/terraform \
  --push http://localhost:8000/api/v1/runs \
  --api-key $WAFPASS_API_KEY

🎨 Code style & guidelines

  • Formatter: ruff format with line length 100.
  • Linter: ruff check for imports, complexity, and style.
  • Typing: annotate public APIs; run mypy --strict in CI.
  • Async: parser discovery and control evaluation run concurrently via asyncio.gather.
  • Immutability: wafpass-core result models as Pydantic objects; avoid mutating raw dicts.
  • Controls as data: control definitions live in YAML; engine code only interprets them.
  • Plugins: expose hook specs in wafpass.hookspecs; implement via entry points.
  • Errors: raise WafPassError with a stable error code; CLI catches and exits with a documented status.
# Local quality gates
ruff check src tests
ruff format --check src tests
mypy src
pytest

📄 The result contract: wafpass-result.json

The engine's only output that downstream components consume. It is versioned, self-describing, and contains no raw credentials.

🧪 Testing strategy

  1. Parser tests: feed real IaC fixtures and assert the resource graph is extracted correctly.
  2. Control tests: parametrised tests for each control against passing and failing fixtures.
  3. Schema tests: every generated result validates against the Pydantic model.
  4. CLI tests: use click.testing.CliRunner to exercise commands and exit codes.
  5. Integration tests: run wafpass check end-to-end and push to a test server instance.
# tests/controls/test_sec_001.py example
import pytest
from wafpass.evaluator import evaluate
from wafpass.parsers.terraform import parse

@pytest.mark.parametrize("fixture,expected", [
    ("s3_encrypted.wafpass-core.tf", []),
    ("s3_plain.fail.tf", ["SEC-001"]),
])
def test_s3_encryption(fixture, expected):
    resources = parse(f"tests/fixtures/terraform/{fixture}")
    findings = evaluate(resources)
    assert [f.control_id for f in findings] == expected

🚀 Developer onboarding flow

  1. Clone wafpass-core, create a venv, and run pip install -e ".[dev]".
  2. Run wafpass check ./tests/fixtures/terraform --summary to see the engine work.
  3. Read src/wafwafpass-core/scanner.py and src/wafwafpass-core/models/result.py for the scan pipeline.
  4. Pick a control in controls/; add a failing and passing fixture, then run pytest.
  5. Open a PR with tests and a changelog entry; CI runs the full matrix across Python 3.11–3.13.
cd wafpass-core
pytest -x
wafpass check ./tests/fixtures/bicep --output json | jq '.summary'

⚙️ Configuration

All behaviour is configurable via environment variables or a pyproject.toml [tool.wafpass] table:

  • WAFPASS_CONTROLS_PATH — directory of YAML control definitions.
  • WAFPASS_MAX_WORKERS — concurrent parser/evaluator workers.
  • WAFPASS_RESULT_MAX_SIZE_MB — hard cap on emitted result JSON.
  • WAFPASS_DEFAULT_SEVERITY — fail threshold for CLI exit code.
  • WAFPASS_LOG_FORMAT — text or json logging.

🔒 Security & trust assumptions

  • The engine never executes IaC; it only reads and parses source or plan files.
  • Plan files may contain sensitive values; sanitise them before sharing results.
  • Keep the API key out of logs and shell history; prefer CI secret stores.
  • Parser plugins run in-process; install only trusted plugins from known sources.
