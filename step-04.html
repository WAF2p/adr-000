A bird's-eye view of every repository, runtime component, and the contracts that connect them. Use this map as a navigation aid when deciding where a change belongs.

🗺️ How the pieces connect

WAF++ is a federation of focused repositories, not a monorepo. Each box below is a real git repository under the umbrella directory. The arrows show the dominant data flow; the dashed line marks the central wafpass-result.json contract.

🧭 Reading the map

  • Start at the top with the framework docs and controls — this is the knowledge layer.
  • Move down to wafpass-core (wafpass-core), the only component that parses IaC and evaluates controls.
  • The dashed arrow is wafpass-result.json; every downstream consumer depends on this contract.
  • Server is optional for local CLI usage, but required for dashboard, MCP, and historical reporting.
  • Tools can bypass the server (e.g., GitHub Action runs wafpass check directly) or push results to it.

🔗 Where to open issues / PRs

  • Docs or control content → framework
  • Scan logic, CLI, result schema → wafpass-core
  • API, auth, persistence → wafpass-server
  • UI, charts, dashboard → wafpass-dashboard
  • AI assistant tooling → wafpass-mcp
  • CI/CD integration → wafpass-action
  • Website, blog, Antora layout → waf2p.github.io
