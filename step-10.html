Getting Started

Enough reading — time to run the stack. This step gives you the clone layout, the local stack command, per-repo workflows, and a checklist to verify you are productive.

📥 Clone layout

mkdir waf++
cd waf++
# framework has two branches: main-de and main-en; check out each into its own directory.
git clone --single-branch --branch main-de https://github.com/WAF2p/framework.git framework
git clone --single-branch --branch main-en https://github.com/WAF2p/framework.git framework-en
git clone https://github.com/WAF2p/waf2p.github.io.git
git clone https://github.com/WAF2p/pass.git
git clone https://github.com/WAF2p/wafpass-server.git
git clone https://github.com/WAF2p/wafpass-dashboard.git
git clone https://github.com/WAF2p/wafpass-mcp.git
git clone https://github.com/WAF2p/wafpass-action.git

🚀 Run the local stack

There is no umbrella docker-compose.yml in this ADR. Start each component from its own directory:

# 1. Start PostgreSQL and wafpass-server
cd wafpass-server
pip install -e ".[dev]"
alembic upgrade head
uvicorn wafpass_server.main:app --reload

# 2. In another terminal, start the dashboard
cd ../wafpass-dashboard
npm install
npm run dev

# 3. Run a scan and push it to the server
cd ../pass
wafpass check ./dummy_code --output json \
  --push http://localhost:8000/api/v1/runs --api-key key

See each repo's README.md for exact environment variables and ports.

📚 Documentation workflow

Edit framework (branch main-de) / framework-en (branch main-en) .adoc files and preview through the website repo.

cd waf2p.github.io
task deps:install
task site:serve
# → http://localhost:8000

🐍 Engine workflow

Develop in pass/ with an editable install.

cd pass
pip install -e .
pytest

⚙️ Server workflow

cd wafpass-server
pip install -e ".[dev]"
export DATABASE_URL=postgresql+asyncpg://.../wafpass
alembic upgrade head
uvicorn wafpass_server.main:app --reload

💻 Dashboard workflow

cd wafpass-dashboard
npm install
npm run dev
# → http://localhost:5173

🤖 MCP workflow

cd wafpass-mcp
pip install -e ".[dev]"
# Then configure Claude Desktop per README.md

✅ Onboarding checklist

  • Read this ADR (ADR-000).
  • Start wafpass-server and wafpass-dashboard locally by following their README.md files.
  • Open the dashboard and log in with the seeded admin account.
  • Run wafpass check ./dummy_code --summary from the pass repo to see the CLI in action.
  • Push a result to the local server and view it in the dashboard.
  • Read the per-repo README.md and TECH.md / AGENTS.md for the component you will work on.
  • For docs work: run task site:serve in waf2p.github.io and edit .adoc files in framework (branch main-de) / framework-en (branch main-en).
  • For AI/MCP work: follow wafpass-mcp/README.md to connect Claude Desktop.

📜 Conventions & decisions

  1. Single result schema: wafpass-result.json is the only contract between engine, server, dashboard, and exports.
  2. Versioned API: all server endpoints live under /api/v1; unversioned paths were removed.
  3. Monorepo-ish layout: each component is a separate git repo under a common umbrella directory; there is no shared orchestration file in this ADR.
  4. Docs separate from site: framework content lives in framework / framework-en (same repository, branches main-de / main-en); the website consumes them as Antora sources.
  5. Controls as data: WAF++ controls are YAML files, updated independently of the engine.
  6. SSO-ready: the server supports OIDC/SAML2 SSO; production brings its own IdP.
  7. Exclusion policy: demo, validation, UI widget, and AI-tooling folders are kept out of the core architecture ADR.
